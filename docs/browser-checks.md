# Manual browser acceptance checks

These checks require real Chrome and Firefox. Mock API tests do not establish browser compatibility. Use disposable browser profiles, disable native bookmark sync, and export bookmarks using the browser's own manager first.

1. Start the backend. Load each browser-specific extension build following the README. In Chrome A make toolbar bookmarks named `A`, `B`, an empty folder, and a nested folder containing two ordered bookmarks. Include names with Unicode and a bookmark whose title is empty. In Firefox B make a distinguishable bookmark so replacement is visible.
2. In Chrome A connect to the server, enter `research`, and click **Use profile**. Since the name is missing, it should seed the collection from this browser without a creation dialog. Confirm `/api/profiles/research` contains the hierarchy, titles, array ordering, empty folder, and a server timestamp.
3. In Firefox B connect and enter `research`. Check the displayed counts and replacement warning; cancel once and verify no changes. Use the profile again and confirm. Verify the original local tree is in exported recovery snapshots, all requested bookmarks appear, empty folders survive, and permanent roots remain.
4. Add/rename/delete/reorder Chrome bookmarks. Wait roughly seven seconds with browser awake. Verify the timestamp advances once per changed snapshot. Leave Firefox open for five minutes and verify it applies the changes without further uploads. Repeat in the opposite direction.
5. Add Firefox menu bookmarks and, where available, mobile bookmarks; sync to Chrome. Verify the fallback folders under Other bookmarks. Edit their contents, sync back to Firefox, then Chrome again. There must be no doubled wrapper folders, lost items, or reordered siblings. Preserve separators as documented in the README. Do not rename reserved fallback folders.
6. Stop the server. Edit Chrome bookmarks. Wait for an upload attempt and verify an error and retained dirty state. Restart the server and select Sync now or wait for an alarm. The local change must arrive. Close/reopen the browser during the outage and repeat.
7. Conflict: bind both to the same revision, take Firefox offline and edit locally, then commit a Chrome edit. Reconnect Firefox and Sync now. Confirm the server version wins, Firefox's pending tree is in exported snapshots, conflict status is visible, and no subsequent timestamp/upload loop occurs.
8. Chrome worker restart: inspect extension service worker, then close DevTools (which keeps workers alive). Make a local edit, stop the worker via extension tools before debounce expires, and wait for retry/poll. The dirty tree must upload. Repeat restarting during a remote restore with many bookmarks: automatic sync must pause on interrupted restore, retain the pre-restore snapshot, and allow recovery. Test Firefox event-page unloading similarly.
9. Enter `work` from another browser profile; it should be seeded from that browser's current bookmarks. Switching to existing `research` must require confirmation, retain the previous local tree snapshot, and thereafter isolate changes from `work`. Rename a profile and rebind other browsers to its new name.
10. Simulate an API restore failure using browser debugging or a mocked rejected `bookmarks.create`. Verify error state, paused auto sync, saved snapshot, no uploading of the partial tree, and working recovery. Export snapshots, then import the exported file and confirm the recovered tree.
11. With auto disabled, local changes must remain pending but not upload on an alarm. Sync now explicitly reconciles. Enable auto and check five-minute alarm recreation after browser restart.
12. Verify behavior for a read-only managed root, duplicate account/local Chrome roots, or an unknown root: extension must refuse destructive restoration with an actionable error. Never test this first on your only bookmark copy.

Record browser versions, operating system, cases passed, and any root/API errors. This repository does not claim those real-browser checks were executed unless a test report explicitly records them.
