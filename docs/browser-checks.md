# Chrome and Firefox test checklist

These are manual checks for a real browser. Automated tests use mocks and cannot confirm native bookmark behavior. Use disposable browser profiles, disable native Chrome Sync or Firefox Sync for bookmarks, and export bookmarks using the browser's own manager before testing.

1. Start the server and install the extension in Chrome and Firefox using [the running guide](../RUNNING.md). Create a test tree in Chrome with ordered bookmarks, a nested folder, an empty folder, Unicode titles, and an empty title. Add a distinct test bookmark in Firefox.
2. In Chrome, connect to the server and use a new name such as `research`. Confirm that the server creates the collection from Chrome's current bookmarks. Check the hierarchy and order in the browser and, if useful, at `/api/profiles/research`.
3. In Firefox, connect to the same server and select `research`. Check that local and server counts are shown. Cancel the replacement once and confirm the local tree is unchanged. Bind again, confirm, then check that the original Firefox tree is available as a recovery snapshot and the Chrome tree appears in Firefox.
4. Add, rename, delete, and reorder bookmarks in Chrome. Wait about seven seconds while the browser is awake; verify the server revision advances. Leave Firefox running for up to five minutes, or choose **Sync now**, and verify the changes arrive. Repeat with Firefox as the source.
5. Put bookmarks in Firefox's menu and mobile roots where available, then sync to Chrome. Check the documented fallback folders under Other bookmarks. Sync back and forth more than once; fallback folders should not duplicate and sibling order should remain stable. Check separator representation. Keep reserved `[bookmarksman-root:...]` and `[bookmarksman:...]` marker names unchanged.
6. Make a local change while the server is stopped. Confirm the popup reports the connection problem and the change is retried after the server returns. Repeat after closing and reopening the browser during the outage.
7. For a conflict, start both browsers at the same revision. Make a local Firefox change, then commit a different Chrome change. Reconcile Firefox. The server version should be applied, the pending Firefox tree should be in recovery snapshots, conflict status should be visible, and no repeated upload should follow.
8. Test background restart behavior in a disposable profile: restart Chrome's extension worker or let Firefox unload its background page around a pending upload and around a large remote restore. Confirm pending changes eventually retry. If a restore is interrupted, automatic sync should pause and the pre-restore snapshot should remain available.
9. Bind another browser profile to a new name such as `work`; it should initialize independently. Switch between `work` and `research`, rename a collection, and confirm other browser profiles can select its new name. Existing collections require confirmation before local replacement.
10. With automatic sync disabled, verify local changes are not uploaded until **Sync now** or automatic sync is re-enabled. Re-enable sync and check that polling resumes after the browser restarts.
11. If possible, test a managed or unknown bookmark root in a disposable profile. The extension should explain that it cannot safely map the tree and stop before deleting local bookmarks.

If any step fails, note the browser version, operating system, popup status, and extension console error. Use the recovery snapshot controls to export a copy before attempting recovery. Do not use a primary bookmark profile until replacement and recovery behavior have been checked.
